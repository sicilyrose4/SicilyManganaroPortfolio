Workshop Comms Planner - Internship Project

A calendar feature that allows users to organize and plan internal communications in advance. I collaborated with engineers to shape the experience from early concepts to final implementation.

ROLE
Product Designer, Intern
TEAM
Me, a project manager, and engineers
TIMELINE
11 weeks, summer 2026

Problem

Internal communications teams usually plan their communications well in advance, anywhere from a month to a full year out, working through the when, what, and who. Teams often have a large amount of sends already planned for the future, all needing a place to stay organized. Currently, messages are sent using Workshop, but the planning happens outside of it, using spreadsheets, docs, or other calendar tools.

This creates a gap between planning and execution for Workshop users.

Solution

The solution to this problem is: planned content!

Planned content is a new type of content on the calendar that acts as a placeholder on the calendar that can be configured and converted over time. It can be thought of as jotting something down in pencil that takes shape as it moves towards a send.

As a result, Workshop users can now use Cici, the AI agent, to add months of plans to their calendar with one click.

Process

The design process started considering a user’s full experience while planning internal company communications. I sat in on customer calls, which helped me understand their experience firsthand.

Before designing any UI, I built out some user flows so I could visualize how a user would perform actions for both manually adding planned content to the calendar, and planning with Cici.

Testing Cici

Before designing anything, I tested what Cici’s AI model could already do with planning, so the engineers knew where to improve it. I used real comms plans that current customers shared with us, like a nonprofit’s annual plan and a strategic plan with open gaps, and evaluated each response. Four patterns stood out:

01.  Ask before advising

The biggest gap. On open-ended prompts like “where do I start?”, Cici gave advice without asking a single clarifying question.

02.  Ground it in the file

Cici read uploaded plans but often fell back on generic advice instead of the plan in front of it.

03.  Plans, not tutorials

Responses explained how to use Workshop’s tools instead of proposing specific dates, segments, and sends.

04.  Consistency

Quality tracked how specific the prompt was. A clear request plus a detailed file produced the strongest plan.

The engineers and I shared these findings with the team as priorities for improving Cici. The version we designed asks clarifying questions before it drafts a plan.

2 MAIN PROJECT PHASES:

  1. 01.Giving users the ability to manually create planned content
  2. 02.Giving Cici (AI agent) the ability to add planned content

01. Manually creating planned content

The first phase gave users a way to add planned content by hand. From the calendar, a user hovers over a day, chooses “Add planned content,” and fills in a side panel with a send date, an optional time, a title, a campaign, and a description. Nothing gets sent: it’s a placeholder they can shape over time.

→ →
  1. 1Choose “Plan content” on any day
  2. 2Fill in the date, title, and details
  3. 3It shows on the calendar as Planned

A closer look at my thought process - splitting date and time

Workshop’s picker asked for a time with every date, but plans made months out often don’t have one yet. I split them so the time is optional, and the new time picker became part of Workshop’s design system.

→
  1. 1Pick a send date
  2. 2Add a time, optional

Editing, deleting, and turning plans into drafts

Once something is on the calendar, clicking it opens a quick view with the owner and send date. From there, users can edit the details, delete it, or choose “Create draft” to turn the plan into a real email that opens in the editor with their description already filled in.

→ →
  1. 1Click it to open a quick view
  2. 2Edit the details
  3. 3Or delete it, after a confirmation
→
  1. 1Choose “Create draft”
  2. 2Pick the email editor
→
  1. 3The plan’s description carries over to pre-fill Create prompt
  2. 4It shows on the calendar as a Draft

02. Using AI to create content

The second phase let Cici, Workshop’s AI agent, build the plan. A user opens Cici from the calendar and either imports an existing comms plan (a doc or spreadsheet) or describes what they need. Cici asks clarifying questions, drafts the plan, and adds it to the calendar as planned content the user can review and edit, by chatting with Cici or by hand.

→ →
  1. 1Open Cici from the Plan icon
  2. 2Upload a plan or describe what you need
  3. 3Review the plan Cici drafts
→
  1. 4Planned content loads onto the calendar
  2. 5Planned content can be viewed on the calendar

Big design question - where should Cici live?

Deciding how Cici would show up on the calendar was one of the biggest design decisions of the project. I went through a lot of iterations, from a “Plan with Cici” button that opens a chat panel to different header placements, and tested whether the calendar should shrink to five days or keep all seven when the chat is open.

Wireframes and hi-fi explorations for a dedicated Cici chat in the calendar.

We landed on a new side navigation on the left of the calendar. Users open Cici with the “Plan” sparkle icon, and the calendar resizes as the chat opens, so content Cici creates appears in real time.

Suggested prompts

I also gave design input on how Cici’s suggested prompts should change on the calendar, so a new chat starts with planning tasks like mapping out next month’s comms, checking for send conflicts, or turning notes into a plan.

Designing for an AI agent meant designing the moments around it: when Cici should ask instead of answer, how a user reviews a draft before anything lands on the calendar, and how they correct it.

Outcome

Manually adding planned content shipped to Workshop customers during my internship, and planning with Cici is set to ship next.

Communications teams can now keep their plans in the same place they send from, and turn a placeholder into a real send when it’s ready. My internship ended before the Cici features launched, so I didn’t get to see them go live.

Beyond the 11 weeks

Some features I designed during the 11-week project didn’t make it into the build. These are the ones I’d pick back up first.

List view

A list view of the calendar, with filters and bulk actions, so teams can manage months of plans at once.

Planned content in campaigns

Linking planned content to a campaign, so it shows on the campaign page with a Planned badge.

Prompt library

A library of ready-made prompts, sorted by category, that drops a prompt straight into the Cici chat.

Conflicts on the calendar

Flagging conflicts, like overlapping sends to the same audience, right on the calendar day.

Assigning to a teammate

Assigning planned content to someone on the team, so it’s clear who owns each send.
